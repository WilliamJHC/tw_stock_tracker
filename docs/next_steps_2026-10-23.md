## 新發現：鎖定流程有一個雞生蛋問題
- §8 第 1 項要求「V2 池量測數字貼在 §2.1，**並與腳本輸出核對**」。
- 但 `run_ep_backtest.py` 的 `main()` 先做 `read_lock()` → §8 沒鎖就 `SystemExit`，根本走不到 `load_universe()`。**照文件字面，量測拿不到，鎖定就做不完**——這很可能是卡住的原因之一。
- 另外 `load_universe()` 回傳的 `info` 沒有「最後一根 bar 日期」，但 §8 第 1 項要這個數字。
- 解法（只載入股票池，不產生任何訊號或績效，鎖定前跑是安全的），從專案根目錄：

```
.venv\Scripts\python -c "import sys; sys.path.insert(0,'scripts'); import run_ep_backtest as r; raw,_,_,i=r.load_universe(); i['incomplete']=len(i['incomplete']); print(i); print('last bar', max(b['date'] for bars in raw.values() for b in bars))"
```

  把輸出貼進 §2.1 與 §8 第 1 項即可。之後若想讓流程自洽，可加一個 `--measure-only` 旗標（只跑 `load_universe()` 並印出），但這會改到腳本，要在鎖定 commit 之前做。
- 注意：關卡 5「前半段 < 100 筆」那個顧慮要看訊號數，屬於結果，**鎖定前不要量**；接受它可能判「樣本不足」。
