# 0006. 「現價」跨 quote/chart/monitor 三處來源，刻意不收斂成單一介面

## 狀態

已接受（原始判斷定案於 2026-08-21 的 `docs/adr/0001-target-price-ownership.md`「考慮過但拒絕的方案」一節，列為架構調查候選 11、判定 Worth exploring；本文件為 2026-09-08 `/improve-codebase-architecture` 架構調查重新核對後補記，把散落在 `CONTEXT.md` 詞條與 ADR 0001 一段拒絕理由裡的判斷，固定成一份查得到的獨立紀錄）

## 背景

`CONTEXT.md`「現價」詞條記載：這個專案裡「股票現在的價格」沒有單一權威來源，依情境取自三個地方：

- `src/data_sources.get_quote(code)`（592 行起）——即時單筆報價，`pipeline.build_stock_payload()`（118 行）轉發成 payload 的 `quote` 欄位，前端多數地方讀 `d.quote.price`。
- 日線圖表最後一筆收盤價——只在 `static/index.html` 畫圖表覆蓋線時使用，可能落後於盤中即時報價。
- `src/monitor.py:203`（`price = prices[-1] if prices else None`）——用當日 tick 序列最後一筆當現價，餵給 `src/alerts.py` 的告警判斷，跟上面兩個不是同一條資料流。

這三者曾經因為前端拿錯來源而顯示不一致（`ADR 0001` 背景段記載的 `788e207`/`daab540` 教訓）。`ADR 0001` 決定新增 `target_price` 欄位解決當時具體的那個 bug，但明確把「順便統一現價本身跨三處的來源分歧」列為拒絕方案，理由是範圍會擴大到 `monitor.py`/`data_sources.py`，屬於規模不同的另一個問題，留給未來單獨評估——即架構調查候選 11。

`2026-09-08` 的架構調查重新核對三個引用點（`data_sources.py:592`、`pipeline.py:118`、`monitor.py:203`）仍然成立、尚未被後續任何改動處理，判定維持 Worth exploring。本文件記錄「維持現狀」本身的理由與未來重新評估的觸發條件，避免下一輪架構調查再花時間重新推導一次同樣的結論。

## 決策

**三處「現價」維持獨立實作，不收斂成單一介面。**

## 為什麼維持現狀

三個「現價」目前服務三種本質不同的情境，收斂的刪除測試（拿掉其中一個會不會讓複雜度收斂到一個更小的介面後面）不明確通過：

- **即時單筆報價**（`get_quote()`）：使用者主動查詢或前端輪詢時要的「現在」，需要低延遲、單一時間點。
- **日線圖表最後收盤**：屬於歷史 K 棒序列的一部分，天生就是「日終」粒度，跟盤中即時報價本來就是不同更新頻率的資料。
- **`monitor.py` 的 tick 序列末筆**：即時監控/告警管線專用，消費端（`alerts.py` 的 VWAP/ORB 判斷）要的是跟同一批 tick 資料同源、時間戳精確對齊的價格，不是跨資料源合併後的「代表值」。

強行收斂成一個 `get_current_price()`，要嘛得讓它對外暴露「你要哪種粒度/情境」的參數（等於把現在三個呼叫端各自明確的意圖，換成一個新函式裡的分支邏輯，複雜度沒有減少，只是換了地方），要嘛選一種語意當預設、犧牲另外兩種情境的精確性——目前沒有證據顯示這三者之間曾經、或需要互相比較，跟 `ADR 0001`「把 `alerts.py` 的 VWAP/ORB 突破判斷也併入同一個介面」那條拒絕理由是同一個判斷：只是恰好都叫「現價」，資料來源、更新頻率、消費端都不同。

## 考慮過但拒絕的方案

**新增一個 `get_current_price(code, mode)` 統一入口，內部依 `mode` 分派到三個既有實作。** 拒絕理由見上——這只是把分支邏輯搬進一個新函式，三個呼叫端原本各自明確的意圖（「我要即時報價」/「我要圖表收盤」/「我要跟這批 tick 同源的價格」）並不會消失，只是換一層間接。

## 重新評估的觸發條件

以下任一情況發生時，這份決策值得重新打開：

1. **真的出現跨情境不一致造成的 bug**——例如前端某處誤用了三者中錯的一個（如 `daab540` 那類事故），且成因是「三個現價概念本身容易混淆」而非單純的程式碼錯誤（`daab540`/`788e207` 本身已經用 `ADR 0001` 的 `target_price` 欄位解決，屬於不同的問題）。
2. **新功能需要跨情境比較現價**——例如需要同時顯示「即時報價 vs. 圖表最後收盤」的落差，或告警判斷需要接上非 tick 來源的即時報價，此時三者之間才第一次出現「該不該一致」的實質需求。

## 影響

- 無程式碼變更，純文件記錄。
- 未來的架構調查（含 `/improve-codebase-architecture`）掃到這三處「現價」時，應視為已決策事項（維持現狀），不需要重新列為候選——除非上述觸發條件之一成立。
